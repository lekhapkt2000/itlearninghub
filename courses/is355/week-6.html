01 · PHẦN A - ON-CHAIN DATA

On-chain Data là gì?

Tuần 6 là buổi tích hợp (Integration Week) của toàn bộ môn IS355. Nếu các tuần trước tập trung vào từng thành phần riêng lẻ như Smart Contract, Token, NFT, DeFi và ESG, thì ở tuần này sinh viên kết nối chúng thành một hệ thống hoàn chỉnh:

Blockchain ↓ On-chain Data ↓ Data Processing ↓ AI / Machine Learning ↓ Risk / Fraud Prediction ↓ DApp Dashboard
On-chain Data là dữ liệu được ghi nhận và xác thực trên Blockchain: Transaction Hash, From/To Address, Value, Gas, Timestamp, Block Number, Contract Address.

Sinh viên cần phân biệt các thành phần dữ liệu cơ bản trên Blockchain:

Thành phầnVai trò
TransactionMột lần chuyển giá trị/gọi hàm giữa hai địa chỉ, có Hash định danh riêng
BlockTập hợp các Transaction được đóng gói và nối tiếp nhau theo thời gian
AddressĐịnh danh của người dùng (EOA) hoặc Smart Contract trên Blockchain
Smart ContractChương trình lưu trạng thái (State) và xử lý logic on-chain
EventBản ghi Smart Contract phát ra khi có thay đổi trạng thái quan trọng
Token TransferSự kiện chuyển Token (ERC-20/ERC-721) giữa hai địa chỉ

Một Transaction có cấu trúc dữ liệu điển hình:

Transaction ├── Hash ├── From ├── To ├── Value ├── Gas ├── Gas Price ├── Nonce ├── Block Number └── Timestamp

Các Block nối tiếp nhau tạo thành chuỗi, mỗi Block chứa nhiều Transaction - Đây là cơ sở để phân tích số lượng giao dịch, giá trị giao dịch, hoạt động theo thời gian và hoạt động của từng địa chỉ theo trục thời gian.

02 · PHẦN B - EVENT LOGS

Event Logs

Ngoài Transaction thông thường, Smart Contract còn tạo ra dữ liệu riêng thông qua State, Transaction và Event Logs. Với contract GreenLending.vy đã xây dựng ở Tuần 5, các Event như LoanCreated, LoanRepaid, LoanLiquidated chính là nguồn dữ liệu rất tốt cho Analytics.

event LoanCreated:
    loan_id: indexed(uint256)
    borrower: indexed(address)
    amount: uint256

Khi tạo khoản vay #001 với Borrower = 0xABC, Amount = 10,000, Blockchain ghi lại Event:

LoanCreated ├── loan_id = 001 ├── borrower = 0xABC └── amount = 10,000

DApp có thể sử dụng Event để xây dựng cả một dòng chảy phân tích:

Transaction History ↓ Analytics ↓ Dashboard ↓ AI Dataset

Từ một chuỗi Event LoanCreated → LoanCreated → LoanRepaid → LoanCreated → LoanLiquidated → LoanCreated, có thể thống kê ngay: Total Loans, Active Loans, Repaid Loans, Liquidated Loans, Default Rate.

04 · PHẦN D - KẾT NỐI BLOCKCHAIN BẰNG WEB3.PY

Data Pipeline: Kết nối Blockchain bằng Web3.py

Kiến trúc dữ liệu đầy đủ của một hệ thống Analytics:

Blockchain ↓ RPC / API (Alchemy, Infura) ↓ Data Extraction (Web3.py) ↓ Pandas DataFrame ↓ ML Model ↓ DApp Dashboard

Kết nối RPC và kiểm tra trạng thái kết nối:

from web3 import Web3

w3 = Web3(Web3.HTTPProvider("YOUR_RPC_URL"))

print(w3.is_connected())  # True

Đọc một Block cụ thể:

block = w3.eth.get_block(100)
print(block)
# Block Number, Timestamp, Transactions, Gas Used, Gas Limit

Đọc một Transaction cụ thể:

tx = w3.eth.get_transaction("TRANSACTION_HASH")
print(tx)
# from, to, value, gas, gasPrice, nonce, blockNumber

Truy vấn toàn bộ Event LoanCreated từ Smart Contract Green Lending (ABI được biên dịch từ Vyper ở Tuần 5) và chuyển thành pandas.DataFrame:

from web3 import Web3
import pandas as pd

# 1. Kết nối RPC và khởi tạo Contract
w3 = Web3(Web3.HTTPProvider("https://eth-sepolia.g.alchemy.com/v2/YOUR_API_KEY"))
contract_address = "0xYourGreenLendingContractAddress"
contract_abi = [...]  # ABI được biên dịch từ Vyper ở Tuần 5

contract = w3.eth.contract(address=contract_address, abi=contract_abi)

# 2. Truy vấn Event "LoanCreated" từ Block quá khứ
event_filter = contract.events.LoanCreated.create_filter(fromBlock=1000000, toBlock='latest')
events = event_filter.get_all_entries()

# 3. Chuyển đổi dữ liệu Event thành Pandas DataFrame
loans_data = []
for event in events:
    args = event['args']
    loans_data.append({
        'loan_id': args['loan_id'],
        'borrower': args['borrower'],
        'amount': args['amount'] / 10**18,       # Convert Wei to ETH
        'collateral': args['collateral'] / 10**18,
        'esg_score': args['esg_score']
    })

df = pd.DataFrame(loans_data)
df['collateral_ratio'] = (df['collateral'] / df['amount']) * 100

05 · PHẦN E - MACHINE LEARNING CHO BLOCKCHAIN

Machine Learning cho Blockchain

Blockchain lưu trữ rất nhiều dữ liệu, nhưng dữ liệu nhiều không đồng nghĩa với việc con người có thể phát hiện tất cả hành vi bất thường. AI có thể hỗ trợ:

Transaction Data ↓ Feature Engineering ↓ Machine Learning ↓ Risk Score

Fraud Detection

So sánh hành vi giữa một địa chỉ bình thường và một địa chỉ bất thường:

Địa chỉTần suất giao dịchGiá trị trung bình
Bình thường10 transactions/day$500
Bất thường1,000 transactions/hour$50,000

Khi phát hiện lệch chuẩn, hệ thống có thể gắn cờ ⚠ Suspicious Activity.

Anomaly Detection

Một số đặc trưng (Feature) thường dùng: Transaction Frequency, Transaction Value, Unique Addresses, Gas Usage, Time Interval, Token Transfer.

Normal: 10 → 20 → 15 → 18 transactions Abnormal: 10 → 12 → 15 → 1,500

Thuật toán

NhómThuật toán tiêu biểu
Unsupervised LearningIsolation Forest, One-Class SVM, DBSCAN
Supervised LearningLogistic Regression, Random Forest, XGBoost

Feature Engineering

Từ dữ liệu giao dịch thô, tổng hợp thành một Feature Vector theo từng địa chỉ:

Address A Tx Count = 150 Avg Value = 850 Unique Addresses = 37 Avg Interval = 2.5h

06 · PHẦN F - GRAPH ANALYTICS & AML

Graph Analytics & AML

Blockchain có thể biểu diễn dưới dạng đồ thị: Address = Node, Transaction = Edge. Một giao dịch riêng lẻ có thể không cho thấy điều gì bất thường, nhưng toàn bộ mạng lưới lại có thể tiết lộ những cấu trúc ẩn.

A → B ↓ B → C ↓ C → D ↓ D → A (Circular Transaction)
Circular Transaction không tự động đồng nghĩa với rửa tiền - Nó chỉ là một tín hiệu cần phân tích thêm.

Graph Analytics giúp phát hiện các cấu trúc mà phân tích giao dịch đơn lẻ khó nhìn thấy: Hub Address (ví gom tiền), Transaction Cluster, Circular Transactions (vòng lặp dòng tiền), Peeling Chains, Fund Flow bất thường.

AML - Anti-Money Laundering là hệ thống và quy trình nhằm phát hiện, ngăn chặn và báo cáo các hoạt động liên quan đến rửa tiền.
Transactions ↓ Risk Engine ↓ Risk Score ↓ Alert

Risk Score được thiết kế dựa trên: Transaction Value, Transaction Frequency, Address History, Counterparty Risk, Transaction Pattern.

Risk ScoreMức độ
0 - 0.3LOW
0.3 - 0.7MEDIUM
0.7 - 1.0HIGH

07 · PHẦN G - SMART CONTRACT SECURITY

Smart Contract Security

Smart Contract có thể quản lý trực tiếp Money, Token, Collateral, Loan, NFT - Nếu có lỗi, tài sản có thể bị mất hoặc hệ thống hoạt động sai. Một số lỗi phổ biến sinh viên cần biết:

Lỗ hổngMô tả
ReentrancyContract gọi External Call, bên nhận gọi ngược lại contract trước khi State được cập nhật xong
Access ControlNgười không có quyền vẫn gọi được function quan trọng (ví dụ mint())
Integer/Arithmetic IssuesLỗi liên quan đến phép tính số học (overflow, underflow, chia làm tròn)
Oracle ManipulationDữ liệu bên ngoài (giá tài sản, ESG Score...) bị thao túng trước khi đưa vào Smart Contract
Logic ErrorsSmart Contract chạy đúng code nhưng sai logic nghiệp vụ

Ví dụ một hàm mint() thiếu kiểm soát quyền - Alice, Bob, Carol và cả Attacker đều có thể gọi được:

@external
def mint(amount: uint256):
    ...

Do đó Smart Contract cần cơ chế phân quyền rõ ràng: onlyOwner, onlyAdmin, hoặc role-based access - Đúng như cách GreenLending.vy ở Tuần 5 giới hạn createLoan() cho admin và updateESGScore() cho oracle.

08 · PHẦN H - KIẾN TRÚC DAPP

Kiến trúc DApp

DApp - Decentralized Application là ứng dụng có một phần logic hoặc dữ liệu được triển khai trên Blockchain.

Một DApp thông thường:

Frontend ↓ Web3 Provider ↓ Smart Contract ↓ Blockchain

Nếu tích hợp AI, kiến trúc có thêm nhánh xử lý Off-chain:

Frontend ↓ Backend / AI API ↓ ML Model ↓ Blockchain

Kiến trúc đề xuất cho Green Finance DApp của môn IS355:

┌──────────────────────────────┐ │ FRONTEND │ │ Streamlit / Web │ └──────────────┬───────────────┘ │ ↓ ┌──────────────────────────────┐ │ WEB3 / API LAYER │ └───────┬──────────────┬───────┘ │ │ ↓ ↓ ┌──────────────┐ ┌─────────────┐ │ Blockchain │ │ AI Engine │ │ Smart Contract│ │ ML Model │ └──────────────┘ └─────────────┘ │ │ └──────┬───────┘ ↓ Analytics Dashboard

Về mặt Tech Stack, bài thực hành Tuần 6 khuyến nghị:

Blockchain & Indexing

Web3.py / Ethers.js, Alchemy hoặc Infura RPC, The Graph (truy vấn GraphQL cho Event Logs)

Data Processing & ML

Pandas, Scikit-learn (RandomForestClassifier, IsolationForest), NetworkX / PyTorch Geometric

DApp Frontend & Dashboard

Streamlit (khuyên dùng cho prototype nhanh) hoặc Next.js + Wagmi + Recharts

Bước 3 - Đánh giá rủi ro vỡ nợ bằng Scikit-learn & hiển thị trên Streamlit

Với dữ liệu mẫu loan_data.csv:

ESGLoanCollateralInterestDefault
9210,00018,00050
858,00014,00060
6512,00013,00091
7215,00018,00071
import streamlit as st
from sklearn.ensemble import RandomForestClassifier

# Giả định mô hình đã được huấn luyện trước đó
# X: [esg_score, collateral_ratio, amount], y: default_status (0: Paid, 1: Default)
model = RandomForestClassifier()

st.title("🌱 Green Finance Analytics & AI Risk Engine")

# Trực quan hóa chỉ số chính
col1, col2, col3 = st.columns(3)
col1.metric("Total Loans Executed", len(df))
col2.metric("Average ESG Score", f"{df['esg_score'].mean():.1f}")
col3.metric("Avg Collateral Ratio", f"{df['collateral_ratio'].mean():.1f}%")

# AI Prediction Panel cho khoản vay mới
st.subheader("🤖 AI Loan Risk Assessor")
input_esg = st.slider("ESG Score", 0, 100, 75)
input_collateral_ratio = st.number_input("Collateral Ratio (%)", value=130.0)
input_amount = st.number_input("Loan Amount (ETH)", value=5.0)

if st.button("Analyze Risk"):
    # Giả lập dự đoán xác suất vỡ nợ từ Model
    risk_prob = model.predict_proba([[input_esg, input_collateral_ratio, input_amount]])[0][1]

    if risk_prob > 0.7:
        st.error(f"🔴 HIGH RISK (Default Probability: {risk_prob*100:.1f}%)")
    elif risk_prob > 0.3:
        st.warning(f"🟡 MEDIUM RISK (Default Probability: {risk_prob*100:.1f}%)")
    else:
        st.success(f"🟢 LOW RISK (Default Probability: {risk_prob*100:.1f}%)")

11 · BÀI TẬP NÂNG CAO

Bài tập nâng cao

Bài 1 - Transaction Anomaly Detection

Xây dựng model phát hiện giao dịch bất thường. Input: Transaction Frequency, Transaction Value, Gas, Time, Counterparties. Output: Normal / Suspicious.
