Trung tâm Thể dục Thể thao (TrungTam_TDTT)

Bài tập Tuần 1 gồm 2 yêu cầu độc lập, sử dụng SQL Server Management Studio để thực hiện. Mỗi yêu cầu nộp thành 1 file script riêng.

Yêu cầu bài tập 1 - Thiết kế và nhập dữ liệu

Cho lược đồ cơ sở dữ liệu "Quản lý Trung tâm Thể dục Thể thao" gồm 6 quan hệ sau:

PHONGTAP (MAPH, TENPHONG, DIACHI, SUCCHUA, TRANGTHAI)

Tân từ: Lưu trữ thông tin phòng tập: Mã phòng, tên phòng, địa chỉ, sức chứa tối đa (số người) và trạng thái phòng (hoạt động, bảo trì, đóng cửa…).

HUANLUYENVIEN (MAHLV, HOTEN, CHUYENMON, SDT, EMAIL)

Tân từ: Lưu trữ thông tin huấn luyện viên: Mã huấn luyện viên, họ tên, chuyên môn (Yoga, Gym,...), số điện thoại và email liên lạc.

Phần I - Ngôn ngữ định nghĩa dữ liệu (Data Definition Language)

  1. Thêm vào thuộc tính GHICHU có kiểu dữ liệu varchar(20) cho quan hệ SANPHAM.
  2. Thêm vào thuộc tính LOAIKH có kiểu dữ liệu là tinyint cho quan hệ KHACHHANG.
  3. Sửa kiểu dữ liệu của thuộc tính GHICHU trong quan hệ SANPHAM thành varchar(100).
  4. Xóa thuộc tính GHICHU trong quan hệ SANPHAM.
  5. Làm thế nào để thuộc tính LOAIKH trong quan hệ KHACHHANG có thể lưu các giá trị là: "Vang lai", "Thuong xuyen", "Vip", …
  6. Đơn vị tính của sản phẩm chỉ có thể là ("cay", "hop", "cai", "quyen", "chuc").
  7. Giá bán của sản phẩm từ 500 đồng trở lên.
  8. Số điện thoại của nhân viên phải bắt đầu bằng chữ số "0".
  9. Mỗi lần mua hàng, khách hàng phải mua ít nhất 1 sản phẩm.
  10. Ngày khách hàng đăng ký là khách hàng thành viên phải lớn hơn ngày sinh của người đó.

Phần II - Ngôn ngữ thao tác dữ liệu (Data Manipulation Language)

  1. Tạo quan hệ SANPHAM1 chứa toàn bộ dữ liệu của quan hệ SANPHAM. Tạo quan hệ KHACHHANG1 chứa toàn bộ dữ liệu của quan hệ KHACHHANG.
  2. Cập nhật giá tăng 5% đối với những sản phẩm do "Thai Lan" sản xuất (cho quan hệ SANPHAM1).
  3. Cập nhật giá giảm 5% đối với những sản phẩm do "Trung Quoc" sản xuất có giá từ 10.000 trở xuống (cho quan hệ SANPHAM1).
  4. Cập nhật giá trị LOAIKH là "Vip" đối với những khách hàng đăng ký thành viên trước ngày 1/1/2007 có doanh số từ 10.000.000 trở lên, hoặc khách hàng đăng ký thành viên từ 1/1/2007 trở về sau có doanh số từ 2.000.000 trở lên (cho quan hệ KHACHHANG1).

CÂU 1 (YC1) · CREATE DATABASE

Đề bài: Tạo cơ sở dữ liệu TrungTam_TDTT, gồm 6 quan hệ PHONGTAP, HUANLUYENVIEN, HOCVIEN, LOPTAP, DANGKY, LICHTAP.

CREATE DATABASE TrungTam_TDTT;
GO
USE TrungTam_TDTT;
GO

CREATE TABLE PHONGTAP
(
    MAPH CHAR(5) PRIMARY KEY,
    TENPHONG VARCHAR(50),
    DIACHI VARCHAR(100),
    SUCCHUA INT,
    TRANGTHAI VARCHAR(20)
);

CREATE TABLE HUANLUYENVIEN
(
    MAHLV CHAR(5) PRIMARY KEY,
    HOTEN VARCHAR(50),
    CHUYENMON VARCHAR(50),
    SDT VARCHAR(15),
    EMAIL VARCHAR(50)
);

CREATE TABLE HOCVIEN
(
    MAHV CHAR(5) PRIMARY KEY,
    HOTEN VARCHAR(50),
    NGSINH SMALLDATETIME,
    SDT VARCHAR(15),
    DIACHI VARCHAR(100),
    GIOITINH VARCHAR(10),
    NGTG SMALLDATETIME
);

CREATE TABLE LOPTAP
(
    MALOP CHAR(5) PRIMARY KEY,
    MAPH CHAR(5),
    MAHLV CHAR(5),
    TENLOP VARCHAR(50),
    NGAYBD SMALLDATETIME,
    NGAYKT SMALLDATETIME,
    TRANGTHAI VARCHAR(20)
);

CREATE TABLE DANGKY
(
    MAHV CHAR(5),
    MALOP CHAR(5),
    NGAYDK SMALLDATETIME,

    PRIMARY KEY (MAHV, MALOP)
);

CREATE TABLE LICHTAP
(
    MALOP CHAR(5),
    NGAYTAP SMALLDATETIME,
    GIOBATDAU TIME,
    GIOKETTHUC TIME,

    PRIMARY KEY (MALOP, NGAYTAP)
);
LÀ GÌ?

CREATE DATABASE tạo 1 CSDL rỗng, sau đó phải USE để chuyển ngữ cảnh làm việc sang CSDL đó trước khi tạo bảng. Khóa chính được khai báo ngay lúc tạo bảng: Khóa đơn dùng PRIMARY KEY ngay sau cột, khóa phức hợp (DANGKY, LICHTAP) dùng dòng PRIMARY KEY (...) riêng ở cuối.

VÌ SAO?

Khóa chính là ràng buộc nội tại của chính bảng đó nên khai báo ngay khi tạo bảng là hợp lý nhất. Khóa ngoại thì khác - Nó tham chiếu sang bảng khác, nên phải đợi bảng được tham chiếu tồn tại trước, do đó để dành sang Câu 2.

CÂU 2 (YC1) · FOREIGN KEY

Đề bài: Tạo khóa chính, khóa ngoại cho các quan hệ trên.

ALTER TABLE LOPTAP ADD CONSTRAINT FK_LOPTAP_PHONGTAP
    FOREIGN KEY (MAPH) REFERENCES PHONGTAP(MAPH);
ALTER TABLE LOPTAP ADD CONSTRAINT FK_LOPTAP_HLV
    FOREIGN KEY (MAHLV) REFERENCES HUANLUYENVIEN(MAHLV);
ALTER TABLE DANGKY ADD CONSTRAINT FK_DANGKY_HOCVIEN
    FOREIGN KEY (MAHV) REFERENCES HOCVIEN(MAHV);
ALTER TABLE DANGKY ADD CONSTRAINT FK_DANGKY_LOPTAP
    FOREIGN KEY (MALOP) REFERENCES LOPTAP(MALOP);
ALTER TABLE LICHTAP ADD CONSTRAINT FK_LICHTAP_LOPTAP
    FOREIGN KEY (MALOP) REFERENCES LOPTAP(MALOP);
LÀ GÌ?

Khóa chính đã được tạo sẵn ở Câu 1, nên Câu 2 chỉ còn thêm khóa ngoại bằng ALTER TABLE ... ADD CONSTRAINT ... FOREIGN KEY (...) REFERENCES ...(...) cho từng cặp bảng có liên kết.

VÌ SAO?

LOPTAP phải đã tồn tại (với khóa chính MAPH ở PHONGTAP, MAHLV ở HUANLUYENVIEN) trước khi tạo được khóa ngoại trỏ tới nó - Đây chính là lý do khóa ngoại luôn phải đợi đến sau khi các bảng liên quan đã hình thành xong.

Dữ liệu ở đây chỉ mang tính minh họa cách viết đúng cú pháp - Khi làm bài thực tế, hãy nhập đủ dữ liệu mẫu trong file PDF đính kèm ở phần Đề bài.

CÂU 1 (YC2 - PHẦN I) · ADD COLUMN

Đề bài: Thêm vào thuộc tính GHICHU có kiểu dữ liệu varchar(20) cho quan hệ SANPHAM.

ALTER TABLE SANPHAM ADD GHICHU VARCHAR(20);
LÀ GÌ?

ALTER TABLE ... ADD thêm 1 cột mới vào bảng đã tồn tại; các dòng dữ liệu cũ sẽ nhận giá trị NULL ở cột mới này.

VÌ SAO?

SANPHAM đã có dữ liệu từ trước, không thể CREATE TABLE lại - Phải dùng ALTER TABLE để bổ sung cột mà không mất dữ liệu hiện có.

CÂU 2 (YC2 - PHẦN I) · ADD COLUMN

Đề bài: Thêm vào thuộc tính LOAIKH có kiểu dữ liệu là tinyint cho quan hệ KHACHHANG.

ALTER TABLE KHACHHANG ADD LOAIKH TINYINT;
LÀ GÌ?

TINYINT lưu số nguyên nhỏ (0-255), phù hợp khi LOAIKH chỉ cần vài mã số cố định.

VÌ SAO?

Đề chỉ yêu cầu thêm cột, chưa yêu cầu ràng buộc giá trị - Việc giới hạn LOAIKH chỉ được lưu vài nhãn cụ thể sẽ làm ở Câu 5.

CÂU 3 (YC2 - PHẦN I) · ALTER COLUMN

Đề bài: Sửa kiểu dữ liệu của thuộc tính GHICHU trong quan hệ SANPHAM thành varchar(100).

ALTER TABLE SANPHAM ALTER COLUMN GHICHU VARCHAR(100);
LÀ GÌ?

ALTER COLUMN thay đổi kiểu dữ liệu (hoặc độ dài) của 1 cột đã tồn tại.

VÌ SAO?

varchar(20) ở Câu 1 có thể không đủ chỗ lưu ghi chú dài hơn, nên phải mở rộng độ dài thay vì xóa cột rồi tạo lại.

CÂU 4 (YC2 - PHẦN I) · DROP COLUMN

Đề bài: Xóa thuộc tính GHICHU trong quan hệ SANPHAM.

ALTER TABLE SANPHAM DROP COLUMN GHICHU;
LÀ GÌ?

DROP COLUMN xóa vĩnh viễn 1 cột cùng toàn bộ dữ liệu đã lưu trong cột đó.

VÌ SAO?

Không còn dùng đến GHICHU nữa thì nên xóa hẳn để tránh cột thừa gây rối khi SELECT * sau này.

CÂU 5 (YC2 - PHẦN I) · CHECK ... IN

Đề bài: Làm thế nào để thuộc tính LOAIKH trong quan hệ KHACHHANG có thể lưu các giá trị là: "Vang lai", "Thuong xuyen", "Vip", …

ALTER TABLE KHACHHANG ALTER COLUMN LOAIKH VARCHAR(20);
LÀ GÌ?

LOAIKH cần lưu chuỗi ký tự ("Vang lai", "Thuong xuyen", "Vip"...) nên chỉ cần đổi kiểu dữ liệu từ TINYINT (ở Câu 2) sang VARCHAR(20) để cột có đủ chỗ chứa chuỗi.

VÌ SAO?

Đề bài kết thúc bằng dấu "…" sau "Vang lai", "Thuong xuyen", "Vip" - Nghĩa là danh sách giá trị chưa đóng, còn có thể phát sinh loại khách hàng khác ngoài 3 loại này. Do đó không nên thêm CHECK ... IN (...) giới hạn cứng đúng 3 giá trị như Câu 6 - Làm vậy sẽ vô tình chặn luôn các loại khách hàng hợp lệ khác chưa được liệt kê. Câu hỏi chỉ yêu cầu cột "có thể lưu" được các giá trị dạng chuỗi này, nên đổi kiểu dữ liệu là đủ.

CÂU 6 (YC2 - PHẦN I) · CHECK ... IN

Đề bài: Đơn vị tính của sản phẩm chỉ có thể là ("cay", "hop", "cai", "quyen", "chuc").

ALTER TABLE SANPHAM ADD CONSTRAINT CK_SANPHAM_DVT
    CHECK (DVT IN (N'cay', N'hop', N'cai', N'quyen', N'chuc'));
Cách khác 
ALTER TABLE SANPHAM ADD CONSTRAINT CK_SANPHAM_DVT
    CHECK (DVT = N'cay' OR DVT = N'hop' OR DVT = N'cai'
        OR DVT = N'quyen' OR DVT = N'chuc');

Chuỗi các phép so sánh = nối bằng OR cho kết quả tương đương IN (...), nhưng dài dòng hơn khi danh sách có nhiều giá trị - IN vẫn là cách viết được khuyến khích.

LÀ GÌ?

Cùng kỹ thuật CHECK ... IN như hướng đã cân nhắc ở Câu 5, áp dụng cho cột DVT (đơn vị tính) của SANPHAM.

VÌ SAO?

Khác với Câu 5, đề bài ở đây liệt kê đúng 5 đơn vị tính và không có dấu "…" - Đây là danh sách đóng, cố định, không phải nhập tự do. Vì vậy CHECK ... IN giới hạn cứng là hoàn toàn phù hợp, giúp tránh nhập sai chính tả hoặc phát sinh đơn vị tính ngoài ý muốn.

CÂU 7 (YC2 - PHẦN I) · CHECK

Đề bài: Giá bán của sản phẩm từ 500 đồng trở lên.

ALTER TABLE SANPHAM ADD CONSTRAINT CK_SANPHAM_GIA CHECK (GIA >= 500);
LÀ GÌ?

CHECK với biểu thức so sánh (khác IN) dùng khi ràng buộc là 1 khoảng giá trị chứ không phải danh sách liệt kê.

VÌ SAO?

"Từ 500 đồng trở lên" là điều kiện >=, không thể liệt kê hết giá trị hợp lệ như Câu 6, nên phải dùng phép so sánh trực tiếp.

CÂU 8 (YC2 - PHẦN I) · CHECK ... LIKE

Đề bài: Số điện thoại của nhân viên phải bắt đầu bằng chữ số "0".

ALTER TABLE NHANVIEN ADD CONSTRAINT CK_NHANVIEN_SODT CHECK (SODT LIKE '0%');
LÀ GÌ?

LIKE '0%' khớp mọi chuỗi bắt đầu bằng ký tự "0", dấu % đại diện cho phần còn lại (độ dài bất kỳ).

VÌ SAO?

Ràng buộc "bắt đầu bằng" là ràng buộc về định dạng chuỗi, không phải giá trị cụ thể hay khoảng số - CHECK ... LIKE là công cụ đúng cho trường hợp này.

CÂU 9 (YC2 - PHẦN I) · CHECK

Đề bài: Mỗi lần mua hàng, khách hàng phải mua ít nhất 1 sản phẩm.

ALTER TABLE CTHD ADD CONSTRAINT CK_CTHD_SL CHECK (SL >= 1);
LÀ GÌ?

Ràng buộc đặt trên cột SL (số lượng) của CTHD - Mỗi dòng chi tiết hóa đơn phải có số lượng mua từ 1 trở lên.

VÌ SAO?

"Mua ít nhất 1 sản phẩm" thực chất là ràng buộc số lượng của từng dòng CTHD, không phải trên HOADON - Vì HOADON không lưu trực tiếp thông tin sản phẩm.

CÂU 10 (YC2 - PHẦN I) · CHECK

Đề bài: Ngày khách hàng đăng ký là khách hàng thành viên phải lớn hơn ngày sinh của người đó.

ALTER TABLE KHACHHANG ADD CONSTRAINT CK_KHACHHANG_NGDK CHECK (NGDK > NGSINH);
LÀ GÌ?

CHECK có thể so sánh 2 cột trong cùng 1 bảng với nhau, không chỉ so sánh với 1 giá trị cố định.

VÌ SAO?

Về mặt logic, 1 người không thể đăng ký làm thành viên trước khi họ được sinh ra - Ràng buộc này giữ dữ liệu luôn hợp lý theo đúng ý nghĩa thực tế.

CÂU 1 (YC2 - PHẦN II) · SELECT INTO

Đề bài: Tạo quan hệ SANPHAM1 chứa toàn bộ dữ liệu của quan hệ SANPHAM. Tạo quan hệ KHACHHANG1 chứa toàn bộ dữ liệu của quan hệ KHACHHANG.

SELECT * INTO SANPHAM1 FROM SANPHAM;
SELECT * INTO KHACHHANG1 FROM KHACHHANG;
LÀ GÌ?

SELECT * INTO <bảng mới> FROM <bảng nguồn> vừa tạo bảng mới vừa sao chép toàn bộ dữ liệu, không cần CREATE TABLE riêng.

VÌ SAO?

Các câu sau đều là UPDATE có thể làm sai lệch dữ liệu gốc - Tạo bản sao trước giúp thao tác thử nghiệm trên SANPHAM1/KHACHHANG1 mà không ảnh hưởng đến SANPHAM/KHACHHANG thật.

CÂU 2 (YC2 - PHẦN II) · UPDATE

Đề bài: Cập nhật giá tăng 5% đối với những sản phẩm do "Thai Lan" sản xuất (cho quan hệ SANPHAM1).

UPDATE SANPHAM1
SET GIA = GIA * 1.05
WHERE NUOCSX = N'Thai Lan';
LÀ GÌ?

GIA * 1.05 nghĩa là giữ nguyên 100% giá cũ và cộng thêm 5%, tương đương tăng 5%.

VÌ SAO?

Không dùng GIA = GIA + 5 vì 5% không phải 1 con số cố định mà phụ thuộc vào giá của từng sản phẩm - Phải nhân với hệ số 1.05 để tỷ lệ tăng đúng cho mọi mức giá khác nhau.

CÂU 3 (YC2 - PHẦN II) · UPDATE

Đề bài: Cập nhật giá giảm 5% đối với những sản phẩm do "Trung Quoc" sản xuất có giá từ 10.000 trở xuống (cho quan hệ SANPHAM1).

UPDATE SANPHAM1
SET GIA = GIA * 0.95
WHERE NUOCSX = N'Trung Quoc' AND GIA <= 10000;
LÀ GÌ?

GIA * 0.95 tương đương giảm 5% (giữ lại 95% giá cũ); mệnh đề WHERE kết hợp 2 điều kiện bằng AND.

VÌ SAO?

Phải lọc đúng 2 điều kiện cùng lúc (nước sản xuất và mức giá) - Thiếu 1 trong 2 sẽ giảm giá nhầm cả những sản phẩm không thuộc diện áp dụng.

CÂU 4 (YC2 - PHẦN II) · UPDATE

Đề bài: Cập nhật giá trị LOAIKH là "Vip" đối với những khách hàng đăng ký thành viên trước ngày 1/1/2007 có doanh số từ 10.000.000 trở lên, hoặc khách hàng đăng ký thành viên từ 1/1/2007 trở về sau có doanh số từ 2.000.000 trở lên (cho quan hệ KHACHHANG1).

UPDATE KHACHHANG1
SET LOAIKH = N'Vip'
WHERE (NGDK < '1/1/2007' AND DOANHSO >= 10000000)
   OR (NGDK >= '1/1/2007' AND DOANHSO >= 2000000);
LÀ GÌ?

Điều kiện gồm 2 nhóm độc lập nối bằng OR, mỗi nhóm lại gồm 2 điều kiện nối bằng AND - Dùng dấu ngoặc để phân nhóm rõ ràng, tránh sai thứ tự ưu tiên AND/OR.

VÌ SAO?

Ngưỡng doanh số để đạt Vip khác nhau tùy thời điểm đăng ký (10 triệu nếu đăng ký trước 1/1/2007, chỉ cần 2 triệu nếu đăng ký từ 1/1/2007 trở đi) - Phải tách 2 trường hợp bằng OR thay vì gộp chung 1 điều kiện.
