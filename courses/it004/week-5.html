Trigger trong SQL Server

5 tiếtDatabaseSQL Server

Mục tiêu: Hiểu cách SQL Server tự động thực hiện một nhóm câu lệnh khi dữ liệu trong bảng phát sinh các thao tác INSERT, UPDATE, DELETE.

01 · TRIGGER LÀ GÌ?

Trigger là gì?

Trigger là một đoạn chương trình SQL được gắn với một bảng hoặc view, được SQL Server tự động kích hoạt khi xảy ra thao tác INSERT, UPDATE hoặc DELETE.

Không có Trigger, so với có Trigger

Người dùng ↓ INSERT / UPDATE / DELETE ↓ Trigger được kích hoạt ↓ Kiểm tra / xử lý / thông báo ↓ Dữ liệu được cập nhật

Ví dụ: "không cho phép số lượng sản phẩm nhỏ hơn 0." Khi người dùng chạy UPDATE SANPHAM SET SOLUONG = -10 WHERE MASP = 'SP01';, Trigger phát hiện SOLUONG < 0 → báo lỗi → ROLLBACK → hủy thao tác.

Tại sao cần Trigger?

Trigger thường dùng để tự động kiểm soát dữ liệu ngay tại tầng cơ sở dữ liệu:

  • Kiểm tra dữ liệu: Số lượng sản phẩm ≥ 0
  • Ngăn thao tác không hợp lệ: Không cho xóa khách hàng đã phát sinh giao dịch
  • Tự động cập nhật: Thêm CTHD → tự động cập nhật trị giá hóa đơn
  • Theo dõi thay đổi: Tên khách hàng cũ → mới
  • Đồng bộ dữ liệu: CTHD thay đổi → cập nhật tổng tiền hóa đơn → cập nhật doanh số khách hàng

02 · CÁC LOẠI TRIGGER

AFTER và INSTEAD OF

SQL Server hỗ trợ hai loại Trigger chính. SQL Server không hỗ trợ BEFORE TRIGGER theo cách một số hệ quản trị CSDL khác có.

AFTER - Chạy sau khi thao tác DML hoàn tất thành công (AFTER INSERT, AFTER UPDATE, AFTER DELETE). INSTEAD OF - thay thế thao tác DML ban đầu bằng các câu lệnh định nghĩa bên trong Trigger.

LoạiCách hoạt độngVí dụ
AFTERThao tác gốc xảy ra trước, Trigger xử lý sauKiểm tra và cập nhật dữ liệu
INSTEAD OFTrigger thay thế thao tác gốcKhông cho phép xóa
BEFOREKhông hỗ trợ trong SQL Server-
AFTER: DELETE → Xóa dữ liệu → Trigger → Xử lý tiếp INSTEAD OF: DELETE → Trigger → KHÔNG thực hiện DELETE gốc

03 · CÚ PHÁP TRIGGER

Cú pháp tạo Trigger

CREATE TRIGGER <Tên_Trigger>
ON <Tên_Bảng>
AFTER | INSTEAD OF INSERT, UPDATE, DELETE
AS
BEGIN
    -- Các câu lệnh xử lý
END;

FOR cũng có thể được dùng thay cho AFTER.

Giải thích từng thành phần

CREATE TRIGGER trg_AfterInsert_KhachHang
ON KHACHHANG
AFTER INSERT
AS
BEGIN
    -- xử lý
END;

CREATE TRIGGER tạo Trigger mới. Tên nên dễ hiểu, ví dụ trg_AfterInsert_KhachHang, trg_CheckQuantity_SanPham, trg_PreventDelete_NhanVien. ON KHACHHANG gắn Trigger vào bảng đó. AFTER INSERT chạy sau khi có INSERT. BEGIN...END chứa các câu lệnh thực hiện.

Ví dụ - AFTER INSERT

Khi thêm khách hàng mới, hiển thị thông báo:

CREATE TRIGGER trg_AfterInsert_KhachHang
ON KHACHHANG
AFTER INSERT
AS
BEGIN
    PRINT N'Khách hàng mới đã được thêm vào KHACHHANG.';
END;

Thử nghiệm:

INSERT INTO KHACHHANG
VALUES (
    'KH99',
    N'Nguyễn Văn A',
    N'Hà Nội',
    '0909000000',
    '2026-08-11',
    0
);
Người dùng không cần gọi Trigger bằng tay - SQL Server tự động kích hoạt Trigger ngay sau khi INSERT thành công.

Ví dụ - INSTEAD OF DELETE

Không cho phép xóa khách hàng:

CREATE TRIGGER trg_PreventDelete_KhachHang
ON KHACHHANG
INSTEAD OF DELETE
AS
BEGIN
    PRINT N'Không được xóa khách hàng.';
END;

Khi chạy DELETE FROM KHACHHANG WHERE MAKH = 'KH01';, thay vì xóa, hệ thống chỉ in ra "Không được xóa khách hàng."

04 · KIỂM TRA VÀ XỬ LÝ LỖI

Trigger kiểm tra dữ liệu

Bài toán: số lượng sản phẩm trong SANPHAM không được nhỏ hơn 0.

CREATE TRIGGER trg_CheckQuantity_SanPham
ON SANPHAM
AFTER INSERT, UPDATE
AS
BEGIN

    IF EXISTS (
        SELECT *
        FROM SANPHAM
        WHERE SOLUONG < 0
    )
    BEGIN
        RAISERROR (
            N'Số lượng không thể âm.',
            16,
            1
        );

        ROLLBACK;
        RETURN;
    END

END;

Phân tích

IF EXISTS → RAISERROR → ROLLBACK → RETURN → Hủy thao tác sai

IF EXISTS(...) kiểm tra có tồn tại bản ghi vi phạm điều kiện hay không. RAISERROR(N'...', 16, 1) báo lỗi - Mức độ 16 là mức thường dùng để biểu diễn lỗi do người dùng gây ra (dữ liệu nhập sai, vi phạm quy tắc). ROLLBACK hủy giao dịch đang thực hiện, đưa dữ liệu về trạng thái trước đó.

Lỗi hay gặp: gọi RAISERROR và ROLLBACK nhưng quên RETURN ngay sau đó. Nếu Trigger còn câu lệnh nào phía sau, chúng vẫn sẽ tiếp tục chạy dù giao dịch đã bị hủy, có thể gây lỗi hoặc hành vi không mong muốn. Nên tập thói quen luôn viết đủ bộ ba RAISERROR → ROLLBACK → RETURN, không chỉ dừng ở ROLLBACK.

PRINT và RAISERROR - Phân biệt

PRINTRAISERROR
Mục đíchThông báoBáo lỗi
Có thể dừng thao tácKhôngCó
Dùng với ROLLBACKCó thể nhưng không tự độngThường kết hợp
Ví dụ"Đã thêm khách hàng""Số lượng không thể âm"

KIỂM TRA NHANH

Muốn hủy hẳn một thao tác UPDATE khi phát hiện dữ liệu sai trong Trigger, cần dùng thêm lệnh nào ngoài RAISERROR?

✓ Chính xác! RAISERROR chỉ báo lỗi, còn ROLLBACK mới thực sự hủy giao dịch và đưa dữ liệu về trạng thái trước đó.

05 · INSERTED VÀ DELETED

INSERTED và DELETED

Trong Trigger, SQL Server cung cấp hai bảng ảo: INSERTED và DELETED. Chúng chỉ tồn tại trong phạm vi Trigger, chứa dữ liệu liên quan đến thao tác DML đang xảy ra.
Thao tácINSERTEDDELETED
INSERTBản ghi mới-
DELETE-Bản ghi bị xóa
UPDATEGiá trị mớiGiá trị cũ
Mẹo nhớ: INSERTED = cái mới. DELETED = cái cũ / bị xóa.

Thử trực tiếp

Bấm một nút để xem INSERTED/DELETED chứa gì với từng thao tác (ví dụ: đổi tên khách hàng từ "Nguyễn Văn A" thành "Nguyễn Văn B"):

DEMO TRỰC QUAN

DELETED (dữ liệu cũ)
(trống)
INSERTED (dữ liệu mới)
HOTEN = 'Nguyễn Văn A' (bản ghi mới)

INSERT → chỉ INSERTED có dữ liệu · DELETE → chỉ DELETED có dữ liệu · UPDATE → cả hai đều có dữ liệu.

CÂU LỆNH TƯƠNG ỨNG 
INSERT INTO KHACHHANG (MAKH, HOTEN)
VALUES ('KH01', N'Nguyễn Văn A');

Ví dụ - Đọc INSERTED

CREATE TRIGGER trg_AfterInsert_KhachHang
ON KHACHHANG
AFTER INSERT
AS
BEGIN
    DECLARE @MAKH CHAR(4);

    SELECT @MAKH = MAKH
    FROM INSERTED;

    PRINT N'Khách hàng mới được thêm vào với MAKH: '
        + CAST(@MAKH AS VARCHAR);
END;

Ví dụ - Đọc DELETED

CREATE TRIGGER trg_AfterDelete_KhachHang
ON KHACHHANG
AFTER DELETE
AS
BEGIN
    SELECT *
    FROM DELETED;
END;

Ví dụ hoàn chỉnh - Theo dõi thay đổi tên (UPDATE)

Khi UPDATE, DELETED chứa giá trị cũ và INSERTED chứa giá trị mới, nên có thể so sánh "giá trị cũ → giá trị mới":

CREATE TRIGGER trg_AfterUpdate_KhachHang
ON KHACHHANG
AFTER UPDATE
AS
BEGIN

    DECLARE
        @OldName VARCHAR(40),
        @NewName VARCHAR(40);

    SELECT @OldName = HOTEN
    FROM DELETED;

    SELECT @NewName = HOTEN
    FROM INSERTED;

    PRINT N'Tên khách hàng đã thay đổi từ "'
        + @OldName
        + N'" sang "'
        + @NewName
        + N'".';

END;

06 · ỨNG DỤNG THỰC TẾ

Ứng dụng thực tế của Trigger

Lỗi hay gặp: dùng Trigger cho những ràng buộc đơn giản mà CHECK CONSTRAINT hoặc FOREIGN KEY đã làm được (ví dụ chỉ để chặn SOLUONG < 0, hoặc đặt giá trị mặc định). Trigger chạy sau khi thao tác DML đã xảy ra nên tốn thêm chi phí xử lý; chỉ nên dùng Trigger khi logic vượt quá khả năng của Constraint - Ví dụ cần tự động cập nhật dữ liệu ở bảng khác, hoặc kiểm tra điều kiện dựa trên dữ liệu ở nhiều bảng.

Kiểm tra tồn tại trước khi thêm

Không cho phép thêm hóa đơn nếu khách hàng chưa tồn tại:

INSERT HOADON → Lấy MAKH từ INSERTED → Kiểm tra KHACHHANG → Có tồn tại? Có → Cho phép | Không → RAISERROR + ROLLBACK

IF EXISTS kiểm tra có tồn tại dữ liệu thỏa điều kiện; IF NOT EXISTS kiểm tra ngược lại - Không tồn tại dữ liệu thỏa điều kiện.

Trigger tự động cập nhật dữ liệu

Bảng HOADON(MAHD, TRIGIA) và CTHD(MAHD, MASP, SOLUONG, DONGIA). Khi INSERT INTO CTHD, Trigger tự động tính lại TRIGIA và UPDATE HOADON.

Trigger cập nhật doanh số khách hàng

Bài toán nâng cao hơn: thêm/sửa hóa đơn → Trigger tính tổng trị giá → cập nhật DOANHSO trong KHACHHANG.

Không cho xóa dữ liệu đang được tham chiếu

Không cho phép xóa nhân viên nếu nhân viên đã tham gia bán hàng:

DELETE NHANVIEN → Kiểm tra HOADON → Có hóa đơn? Có → ROLLBACK | Không → Cho phép

Tự động cập nhật ngày đăng ký

Khi thêm khách hàng mới, nếu không nhập NGDK, hệ thống tự động lấy ngày hiện tại bằng GETDATE().

Một số bài toán mở rộng

  • Sản phẩm chỉ được thêm vào hóa đơn nếu sản phẩm tồn tại và đủ tồn kho
  • Tổng giá trị trong CTHD phải khớp với HOADON
  • Hóa đơn vượt 1.000.000.000 phải chuyển trạng thái "Kiểm tra đặc biệt"
  • Tổng số lượng sản phẩm bán ra trong một ngày không vượt 10.000 sản phẩm
  • Không cho nhân viên trở thành cấp trên của chính mình

07 · TRIGGER XỬ LÝ NHIỀU DÒNG

Trigger nên tư duy theo tập dữ liệu

Sinh viên thường viết:

DECLARE @MAKH CHAR(4);

SELECT @MAKH = MAKH
FROM INSERTED;

Cách này dễ hiểu khi minh họa một bản ghi, nhưng một câu INSERT INTO ... SELECT ... có thể thêm nhiều dòng cùng lúc.

INSERTED ├── dòng 1 ├── dòng 2 ├── dòng 3 ├── ... └── dòng n
Trigger nên được tư duy theo tập hợp dữ liệu (set-based) thay vì mặc định chỉ có một dòng - Đây là kỹ năng quan trọng khi bước từ bài thực hành sang SQL thực tế. Không nên chỉ tư duy "INSERTED → 1 dòng → 1 biến", mà cần xử lý toàn bộ tập dữ liệu trong INSERTED/DELETED.

08 · QUY TRÌNH XÂY TRIGGER

Quy trình 6 bước

Khi gặp bài tập Trigger, có thể làm theo 6 bước:

1. Xác định sự kiện: INSERT / UPDATE / DELETE ↓ 2. Xác định bảng: ON ... ↓ 3. Xác định loại: AFTER hay INSTEAD OF ↓ 4. Xác định dữ liệu cần kiểm tra: INSERTED / DELETED / bảng khác ↓ 5. Viết điều kiện: IF EXISTS / IF NOT EXISTS ↓ 6. Xử lý: PRINT / RAISERROR / ROLLBACK / INSERT / UPDATE / DELETE

Quản lý Trigger

Xóa Trigger:

DROP TRIGGER trg_AfterInsert_KhachHang;

Xem thông tin Trigger:

SELECT *
FROM INFORMATION_SCHEMA.TRIGGERS;

Cheat Sheet Tuần 5

TRIGGER → Tự động chạy khi DML xảy ra INSERT/UPDATE/DELETE → Các thao tác kích hoạt Trigger AFTER → Chạy sau thao tác DML INSTEAD OF → Thay thế thao tác DML INSERTED → Dữ liệu mới DELETED → Dữ liệu cũ / bị xóa IF EXISTS → Kiểm tra có dữ liệu thỏa điều kiện IF NOT EXISTS → Kiểm tra không tồn tại dữ liệu PRINT → Thông báo RAISERROR → Báo lỗi ROLLBACK → Hủy thao tác / giao dịch
