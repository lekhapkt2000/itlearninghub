01 · INTRODUCTION & OBJECTIVES

Introduction

The final project is a capstone activity to help students apply the knowledge and skills practiced throughout the Blockchain Technology course to build a product or prototype that applies Blockchain in finance, banking, and green finance.

Students must not only deploy a Smart Contract but also demonstrate the ability to:

  • Analyze a real-world problem
  • Identify Blockchain's role in that problem
  • Design a system architecture
  • Build a Smart Contract
  • Process and analyze data
  • Apply AI/Machine Learning where appropriate
  • Build a DApp interface or Dashboard
  • Evaluate the system's correctness, performance, and security
  • Present the research results and the product

Project objectives

On Blockchain - Understand and choose an appropriate Blockchain model; design and deploy a Smart Contract on a test network; interact with the Smart Contract via Web3; use Event Logs to record and retrieve data.

On finance and banking - Be able to model a business process such as Lending, Credit Scoring, Asset Management, Asset Tokenization, Carbon Credit, Green Bond, DeFi, Payments, Transaction Management, Anomalous Transaction Detection, AML, Investment Portfolio Management.

On data and AI - Collect and clean data, build features, analyze data, build and evaluate a Machine Learning model, and feed prediction results into the system.

AI/ML is not mandatory for every topic, but is encouraged for topics involving forecasting, classification, anomaly detection, or recommendation.

On application development - Students build a prototype with a complete operating flow:

User ↓ DApp / Dashboard ↓ Web3 / Backend ↓ Smart Contract ↓ Blockchain

02 · PROJECT TOPICS

Project topics

The project must fall into one of the following directions:

Group A - Green Finance

A1. Green Lending - Build a green lending platform based on ESG Score, Credit Score, Smart Contract, Collateral, Interest Rate. Example: Blockchain-based Green Lending Platform with ESG Credit Scoring.

A2. Carbon Credit - Build a system to tokenize and manage Carbon Credit, optionally extended with Carbon Credit price forecasting:

Carbon Credit ↓ ERC-20 ↓ Mint ↓ Transfer ↓ Retire / Burn

A3. Green Bond - Build a model for issuing and managing a Green Bond on the Blockchain, optionally researching Tokenization, Investor, Issuer, Interest, Maturity, Redemption.

Group B - DeFi & Banking

B1. Decentralized Lending - Build a decentralized lending system with functions: Deposit, Borrow, Repay, Withdraw, Liquidate.

B2. ESG Credit Scoring - Build a credit assessment system based on ESG:

Financial Data + ESG Data + Transaction History ↓ Credit Score ↓ Loan Decision

B3. AI-based Default Prediction - Build a model that forecasts the probability of default (e.g., Default Probability = 82%) and feed the result into a Dashboard.

Group C - Blockchain Analytics & AML

C1. Fraud Detection - Detect anomalous transactions, potentially using Isolation Forest, Random Forest, XGBoost, Autoencoder.

C2. AML Analytics - Analyze fund flows on the Blockchain to detect suspicious transaction patterns (e.g., the loop A ➜ B ➜ C ➜ D ➜ A or a branching structure from a Hub Address), applying Graph Analytics to analyze the transaction network.

Group D - RWA & Tokenization

Asset tokenization, NFT asset certificates, Digital Certificate, Green Asset, Supply Chain Asset. Example: Blockchain-based Green Asset Certification Platform.

Group E - AI + Blockchain

An advanced direction combining Blockchain + Data Analytics + AI. Some topics: AI forecasting DeFi risk, AI fraud detection, AI anomalous-transaction detection, AI green-investment recommendation, AI Carbon Credit price forecasting, AI credit risk assessment.

03 · TOPIC REGISTRATION

Topic registration

Students submit a topic registration by the end of Week 3 or the start of Week 4, using the short template below, so the instructor can confirm the topic fits one of the 5 topic groups and the intended project level before development begins:

1. Tên đề tài: [Tên tiếng Việt + tiếng Anh]
2. Phân loại: [Nhóm A/B/C/D/E] - [Mức độ 1/2/3/4]
3. Bài toán thực tế & Lý do cần Blockchain: [Mô tả trong 3-4 câu]
4. Kiến trúc đề xuất: [Sơ đồ khối đơn giản]
5. Dự kiến Công nghệ (Stack):
   - Smart Contract: Vyper / Solidity
   - AI/Data: Python / Scikit-Learn / NetworkX
   - DApp: Streamlit / React
Registering early helps groups avoid picking a duplicate topic, and it sets the correct evaluation Track (AI/ML or not) from the start, per Section 15.

04 · MANDATORY PROJECT REQUIREMENTS

5 main components

Each group must satisfy all 5 components below - A topic that only simulates Blockchain with a regular database will not be accepted.

Component 1 - Blockchain

Must include at least one real Blockchain component: Smart Contract, Testnet, Transaction, Event, Token, or NFT.

Component 2 - Smart Contract

RequirementExample
Business LogiccreateLoan(), approveLoan(), repayLoan(), liquidateLoan()
Access ControlAt minimum Admin/User roles, or Issuer/Investor/Borrower/Lender
EventLoanCreated, LoanApproved, LoanRepaid, LoanLiquidated
ValidationChecks on Input, Permission, Balance, and business state

Component 3 - Data / Analytics

Students must include at least one data analysis activity:

Metric groupExample
Transaction AnalyticsTotal Transactions, Transaction Volume, Average Transaction, Active Addresses
Financial AnalyticsLoan Volume, Default Rate, Liquidation Rate, Interest Rate
ESG AnalyticsAverage ESG Score, ESG Distribution, ESG vs Default

Component 4 - AI/ML (encouraged, not required)

If AI/ML is used, the group must clearly present:

  • Dataset: the data source, sample size, attributes, and preprocessing method
  • Model: e.g., Random Forest, XGBoost, LightGBM, LSTM, Isolation Forest
  • Evaluation: not just the prediction results, but an appropriate metric - Accuracy, Precision, Recall, F1-score, ROC-AUC, MAE, RMSE depending on the problem

Component 5 - DApp / Dashboard

The product must have an interface for users to interact with: HTML/CSS/JavaScript, React, Streamlit, PySide, or another suitable framework. At minimum, the Dashboard should include:

┌─────────────────────────────┐ │ GREEN FINANCE DApp │ ├─────────┬─────────┬─────────┤ │ Users │ Loans │ Volume │ ├─────────┴─────────┴─────────┤ │ │ │ Analytics Chart │ │ │ ├─────────────────────────────┤ │ Transaction History │ ├─────────────────────────────┤ │ AI Risk Prediction │ └─────────────────────────────┘

05 · DATA REQUIREMENTS

Data requirements

Students may use:

Blockchain data

Testnet, Public Blockchain Data, Transaction Data, Event Logs

Financial data

Public datasets, simulated datasets, datasets built by the group

ESG data

ESG Score, Carbon Emission, Environmental Indicators, Sustainability Indicators

If simulated data is used, the group must clearly state that it is simulated data and explain how it was generated.

06 · SYSTEM ARCHITECTURE REQUIREMENTS

System architecture

The report must include an architecture diagram, for example:

USER │ ▼ ┌────────────────┐ │ DApp / UI │ └───────┬────────┘ │ ┌───────▼────────┐ │ Web3 / Backend │ └───┬────────┬───┘ │ │ ▼ ▼ ┌────────────┐ ┌──────────┐ │ Blockchain │ │ AI Model │ │ │ │ │ │ Smart │ │ Risk │ │ Contract │ │ Score │ └────────────┘ └──────────┘
Architecture note: If an AI model or an ESG Score is used to directly drive a Smart Contract decision (e.g., auto-approving a loan, computing interest), students must clearly explain the mechanism for passing data from Off-chain to On-chain (using an Oracle pattern, Signer Key/ECDSA Verification, or Chainlink Functions) - Avoiding a system that is "centralized in disguise as Decentralized."

07 · PROJECT EXECUTION PROCESS

Project execution process

Phase 1 - Define the problem

The group answers: What is the real-world problem? Why is Blockchain needed? What does Blockchain solve?

Phase 2 - Research

Study existing solutions, related technologies, prior research, and the limitations of current solutions.

Phase 3 - Analysis & design

Build a Use Case, User Flow, System Architecture, Database/Data Model if needed, Smart Contract Architecture.

Phase 4 - Smart Contract

Design ↓ Code ↓ Compile ↓ Test ↓ Deploy

Phase 5 - Data & AI

Collect ↓ Clean ↓ Feature Engineering ↓ Train ↓ Evaluate

Phase 6 - DApp

Frontend ↓ Web3 ↓ Smart Contract ↓ Blockchain

Phase 7 - Integration

Integrate Blockchain + Smart Contract + AI + Dashboard into one unified system.

Phase 8 - Testing

Must test: Smart Contract, Business Logic, Access Control, Transaction, DApp, AI Model.

09 · PERFORMANCE EVALUATION

Performance evaluation

Depending on the topic, the group should evaluate:

GroupMetric
BlockchainGas Used, Gas Cost, Transaction Time
AIAccuracy, F1, Recall, ROC-AUC
DAppResponse Time, Transaction Success Rate
Not all metrics are mandatory - The group chooses the metrics that fit its topic.

10 · SECURITY REQUIREMENTS

Security requirements

The group must analyze at least 3 security risks relevant to the system, e.g.: Reentrancy, Access Control, Integer/Arithmetic Issues, Oracle Manipulation, Front-running, Private Key Security, Input Validation.

For each risk, the group must explain it in exactly three steps: What the risk is ➜ How it could happen ➜ A mitigation.

11 · DELIVERABLES

Deliverables

Each group submits 5 components:

1. Source Code

Smart Contract, Frontend, Backend, AI/ML, Scripts

2. Project report

PDF format

3. Presentation slides

Used for defending the project

4. Demo video

About 5-10 minutes, showing Problem ➜ Solution ➜ Smart Contract ➜ DApp ➜ AI ➜ Demo

5. README

Instructions for installing, configuring, deploying, running the DApp, running AI, and demoing

Academic integrity policy

Absolutely no copying or reusing another student's work for submission. Students must complete their own assignments honestly.

13 · DEMO REQUIREMENTS

Demo requirements

During the defense, the group must demo the product live - Not just show screenshots. Suggested order:

1. Introduce the problem ↓ 2. Introduce the architecture ↓ 3. Demo the Smart Contract ↓ 4. Demo the DApp ↓ 5. Perform a Transaction ↓ 6. Check the Blockchain ↓ 7. Demo the AI ↓ 8. Show the results

14 · DEFENSE QUESTIONS

Defense questions

The instructor may ask across 5 topic groups:

Blockchain

  • Why does this topic need Blockchain?
  • If Blockchain were removed, would the system still work?
  • What does the group's Smart Contract do?
  • Which data is stored on-chain?

Smart Contract

  • Why was the function designed this way?
  • Who has permission to call the function?
  • How does the group handle access control?
  • What security risks exist?

AI

  • Where does the dataset come from?
  • Why was this algorithm chosen?
  • Which metric matters most?
  • Is the model overfitting?

System

  • How does the system architecture work?
  • Is the AI on-chain or off-chain?
  • If Blockchain isn't working, how does the system handle it?
  • If a transaction fails, how does the DApp handle it?

Research

  • What is novel about this topic?
  • Compared to existing solutions, where is the system better?
  • What is the biggest limitation of the topic?

15 · GRADING CRITERIA

Grading criteria

To avoid ambiguity in grading, the 100-point scale is split into 2 Tracks depending on whether the topic uses AI/ML:

CategoryTrack A - With AI/ML
Levels ★★★ & ★★★★		Track B - Without AI/ML
Levels ★ & ★★
Problem analysis & idea1010
Theoretical background & research1010
Smart Contract & Blockchain / Advanced Business Logic2025
Data & AI/ML / On-chain Data Analytics1510
DApp & interactive interface1520
Testing & security1010
Report1010
Demo & presentation1010
Total100105

Track B is for topics that go deep on DeFi Logic/Tokenomics/Security without using AI/ML: Smart Contract & Advanced Business Logic gets 5 extra points for contract complexity, DApp & interactive interface gets 5 extra points for Web3 user experience, while On-chain Data Analytics (Chart/Metrics/Event Indexing) is worth only 10 points.

Whichever Track a group registers in Section 03 (Topic registration) is the one it is graded against - The two Tracks' points are not combined for the same topic.

17 · MINIMUM REQUIREMENTS TO PASS

Minimum requirements to be considered complete

A passing project must demonstrate: A real-world problem ➜ A Blockchain-based solution ➜ A Smart Contract ➜ Actual deployment/testing ➜ An interface or interaction method ➜ Data/experiments ➜ An evaluation of the results.

A project should not be graded highly if it only has:

✗ A nice interface but no real Blockchain.
✗ A simple Smart Contract with no real business problem.
✗ AI run on a dataset while Blockchain only appears in the theory section.

19 · FINAL PRODUCT DIRECTION

Final product direction

The entire IS355 project should aim for the following overall model:

┌──────────────────┐ │ USER │ └────────┬─────────┘ ↓ ┌──────────────────┐ │ DApp / Web UI │ └────────┬─────────┘ ↓ ┌──────────────┴──────────────┐ ↓ ↓ ┌─────────────────┐ ┌─────────────────┐ │ BLOCKCHAIN │ │ AI / DATA │ │ │ │ │ │ Smart Contract │ │ Analytics │ │ Token / NFT │ │ ML Prediction │ │ Transaction │ │ Risk Score │ └────────┬────────┘ └────────┬────────┘ │ │ └──────────────┬─────────────┘ ↓ ┌──────────────────┐ │ GREEN FINANCE / │ │ BANKING SOLUTION │ └──────────────────┘

In this way, the 7 weeks of practice lead very naturally to the project:

Week 1: Green Finance & Blockchain basics ↓ Week 2: Security & Identity ↓ Week 3: Token/Carbon Credit ↓ Week 4: RWA/NFT ↓ Week 5: DeFi/Green Banking ↓ Week 6: Data/AI/DApp ↓ Week 7: Project defense

This is also the structure kept consistent on the website, so students can see at a glance which piece of the final project each week is building.
