01 · WHAT IS BLOCKCHAIN?

What Is Blockchain?

Blockchain is a data structure made of a chain of blocks, stored and synchronized across many computers (nodes) in a distributed network. Each block holds transaction data and is linked to the previous block through a hash value, which makes recorded data very difficult to alter.

Why did Blockchain emerge?

Before Blockchain, transactions (money transfers, purchases, ownership verification...) usually depended on a trusted intermediary - a bank, for example - to confirm and store them. Blockchain emerged (starting with Bitcoin, introduced in 2008) to solve a specific problem: how can two parties who don't know each other (trustless) transact directly, without a single intermediary controlling all the data, while the transaction is still verified and can't be forged.

What problem does Blockchain solve?

Two core problems: double-spending (spending the same digital asset twice) and trust between unfamiliar parties. Instead of relying on a central referee, Blockchain uses the agreement (consensus) of many nodes in the network to confirm that a transaction is valid and unique.

How is Blockchain different from a traditional database?

The differences span several dimensions: who manages the data (one central system vs. many distributed nodes), whether recorded data can be edited/deleted, who controls writing new data, audit capability (whether transaction history is built in or needs to be added separately), and processing speed (depends on the consensus mechanism rather than just hardware). Exercise 1 at the end of this week will ask you to build a detailed comparison table yourself.

02 · CHARACTERISTICS OF BLOCKCHAIN

Characteristics of Blockchain

Blockchain │ ├── Decentralization ├── Transparency ├── Immutability ├── Security └── Traceability

Decentralization

There is no single central point of control. Data is replicated and synchronized across many nodes, each holding a full (or near-full) copy of the Blockchain.

Transparency

Every transaction is recorded openly within the network (depending on whether the Blockchain is public or private) and can be checked and cross-verified by nodes.

Immutability

Data written into a block is very difficult to alter, because each block contains the hash of the block before it. Changing the data in just one block changes that block's hash, which makes every subsequent block no longer match - the network detects the anomaly.

Security

Encryption techniques - hash functions, digital signatures - are used to ensure transactions are authentic and haven't been tampered with in transit.

Traceability

The entire transaction history is fully preserved on the chain, letting anyone trace the origin and path of any asset or transaction at any time.

03 · CORE COMPONENTS

Core Components

Transaction ↓ Block ↓ Hash ↓ Blockchain ↓ Network
ComponentRole
TransactionA unit of data recording one action, e.g. a single money transfer
BlockA collection of transactions plus metadata (timestamp, hash of the previous block...)
HashA unique digital value representing a block's contents, used to link blocks together
BlockchainThe chain of blocks linked together via hashes
NetworkThe set of nodes that maintain, validate, and synchronize the entire Blockchain

04 · HOW IT WORKS

How It Works

A transaction goes through the following steps before becoming a permanent part of the Blockchain:

User creates a transaction ↓ Transaction is broadcast ↓ Network validates it ↓ Transaction is added to a Block ↓ Block is confirmed ↓ Block is added to the Blockchain ↓ Nodes update their data
Remember: A transaction is only considered final once the block containing it has been confirmed and added to the Blockchain - before that, it can still be dropped if the network doesn't reach consensus on it.
