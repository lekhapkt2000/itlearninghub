01 · PART A - THEORY & CRYPTOGRAPHIC FOUNDATIONS

The identity security problem in digital finance

Financial systems handle a great deal of sensitive information (full name, national ID, account, credit profile). A typical eKYC process:

Customer ↓ Provides information ↓ eKYC ↓ Verification ↓ Open account / Transact
If identity is stolen, bad actors can forge profiles, launder money, or seize assets.

02 · CIA MODEL

The three pillars of data security (CIA Model)

  • Confidentiality: Only authorized parties may view the data (solution: Encryption).
  • Integrity: Data cannot be modified without authorization (solution: Hash).
  • Authentication: Confirms the identity of whoever performed an action (solution: Digital Signature).

Example: When a customer transfers 5 million VND through a banking app - Confidentiality ensures no one but the bank and the customer can read the transfer order; Integrity ensures the amount "5,000,000" is not changed to "50,000,000" in transit; Authentication ensures the system knows for certain that this exact customer (not an impersonator) issued the transfer order.

03 · SYMMETRIC & ASYMMETRIC ENCRYPTION

Symmetric encryption vs Asymmetric encryption

Symmetric encryption

Uses one shared key for both encryption and decryption (e.g., AES). Fast, but runs into the hard problem of sharing that key securely.

Plaintext ↓ Encryption + Key Ciphertext ↓ Decryption + Same Key Plaintext

Example: A bank wants to send the instruction "TRANSFER 100 USD". Encrypting it with an AES key turns the transmitted content into a meaningless string like "8A91F2C4...". Only the party holding that exact AES key can decrypt it back into "TRANSFER 100 USD". The problem: both sides must find a way to exchange this AES key securely before transacting - If the key is exposed in transit, anyone who intercepts it can also read the content.

Asymmetric encryption

Uses a key pair: a Public Key (shared openly) and a Private Key (kept absolutely secret). This is exactly how asymmetric encryption solves the "secure key sharing" problem above: The bank encrypts the transfer order with the customer's Public Key, and only the customer - The sole holder of the matching Private Key - Can decrypt it, even though the Public Key is available to anyone.

04 · KEYS & ADDRESSES IN BLOCKCHAIN

Keys & Addresses in Blockchain

Private Key ↓ Public Key ↓ Wallet Address

Private Key proves ownership and is used to sign transactions.

Golden rule

Never commit a Private Key to GitHub, never paste one into public source code. This course uses only Testnet/Local nodes (Ganache/Geth).

05 · HASH VS ENCRYPTION

Hash functions & distinguishing Encryption from Hash

A hash is a one-way function that turns data into a fixed-length string (e.g., SHA-256).

TraitEncryptionHash
PurposeProtects data contentVerifies integrity
ReversibleYes (with the Key)No (one-way function)
Uses a KeyYesNot required
Typical usesAES, RSASHA-256, Keccak-256

06 · DIGITAL SIGNATURE

Digital Signature

A digital signature uses the Private Key to sign a Message Digest (a hash of the data). The recipient uses the Public Key to Verify it.

Core difference: Encryption hides information; Digital Signature verifies the signer and guarantees integrity.

Blockchain transaction flow:

Create Tx ↓ Sign with Private Key ↓ Broadcast ↓ Network Verifies Signature ↓ Accept / Reject

07 · ZERO-KNOWLEDGE PROOF

Zero-Knowledge Proof (ZKP)

ZKP lets a Prover prove to a Verifier that a statement is true without revealing the secret information behind it.
Prover ↓ Proof Verifier ↓ Valid / Invalid
ZKP + ESG application: A company proves it has reached ESG Score ≥ 80 to a bank/auditor without exposing operating reports, costs, or internal production data.

08 · PART B - HANDS-ON LAB

Practice 1: Create & Verify a digital signature (Python Cryptography)

from cryptography.hazmat.primitives.asymmetric import ec
from cryptography.hazmat.primitives import hashes
from cryptography.exceptions import InvalidSignature

# 1. Tạo cặp khóa SECP256K1 (chuẩn Ethereum)
private_key = ec.generate_private_key(ec.SECP256K1())
public_key = private_key.public_key()

# 2. Ký thông điệp (Sign)
message = b"Transfer 100 ETH to Alice"
signature = private_key.sign(message, ec.ECDSA(hashes.SHA256()))

# 3. Xác minh chữ ký (Verify)
try:
    public_key.verify(signature, message, ec.ECDSA(hashes.SHA256()))
    print("Signature Valid")
except InvalidSignature:
    print("Signature Invalid")

# 4. Thử sửa đổi dữ liệu, chữ ký lập tức thất bại
tampered_message = b"Transfer 1000 ETH to Alice"
try:
    public_key.verify(signature, tampered_message, ec.ECDSA(hashes.SHA256()))
except InvalidSignature:
    print("Alert: Message was tampered! Signature Invalid.")
Students should explain: why does changing only the message content immediately invalidate the old signature? This is exactly how Hash ➜ Digital Signature ➜ Integrity connect.

09 · PRACTICE: SMART CONTRACT

Practice 2: ESGCertificate Smart Contract with Event Logs & Access Control (Vyper)

Write the file contracts/ESGCertificate.vy supporting Admin, Company, and Auditor roles, and emitting Events:

# @version ^0.4.3

event DataSubmitted:
    company: indexed(address)
    score: uint256

event CertificateVerified:
    company: indexed(address)
    auditor: indexed(address)
    approved: bool

admin: public(address)
auditors: public(HashMap[address, bool])
esg_scores: public(HashMap[address, uint256])
is_verified: public(HashMap[address, bool])

@deploy
def __init__():
    self.admin = msg.sender

@external
def add_auditor(auditor_address: address):
    assert msg.sender == self.admin, "Only Admin can add auditor"
    self.auditors[auditor_address] = True

@external
def submit_esg_data(score: uint256):
    self.esg_scores[msg.sender] = score
    log DataSubmitted(msg.sender, score)

@external
def verify_certificate(company: address, approved: bool):
    assert self.auditors[msg.sender] == True, "Only Auditor can verify"
    self.is_verified[company] = approved
    log CertificateVerified(company, msg.sender, approved)

10 · PRACTICE: DEPLOY & TESTING

Practice 3: Deploy & test with Ape Framework and local Geth

Step 1 - Start a local Geth node:

geth --dev --http --http.api eth,web3,net --ipcpath /tmp/geth.ipc

Step 2 - Compile the contract:

ape compile

Step 3 - Deployment & interaction script scripts/deploy_esg.py:

from ape import accounts, project

def main():
    # Load account đã import sẵn trong Ape
    dev = accounts.load("is355_")
    dev.set_autosign(True, passphrase="your_passphrase")

    # Deploy contract
    esg_contract = dev.deploy(project.ESGCertificate)
    print(f"Contract deployed at: {esg_contract.address}")

    # Submit ESG Data
    tx = esg_contract.submit_esg_data(85, sender=dev)
    print(f"ESG Data submitted. Tx hash: {tx.tx_hash}")

Step 4 - Run the deployment script:

ape run deploy_esg --network ethereum:local:http://127.0.0.1:8545

Two research directions for Week 2

Direction 1 - ZKP for ESG standard verification

Problem: prove ESG Score ≥ Threshold without revealing revenue data or actual emission figures.

  • RQ1: How do you set up a ZKP circuit (zk-SNARKs) to verify an ESG metric without leaking its input?
  • RQ2: How much gas does it cost to Verify a Proof on an Ethereum Smart Contract?

Direction 2 - AI for eKYC fraud detection

Feature dataset:

FeatureData typeMeaning
Document_Match_ScorefloatHow well the ID photo matches
Face_Match_ScorefloatHow well the face matches
IP_Risk_ScorefloatIP risk level
Device_CountintNumber of accounts created on the same device
Target (Fraud)0 / 10 = Legitimate, 1 = Fraudulent
