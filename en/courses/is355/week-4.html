01 · PART A - LECTURE THEORY

From ERC-20 (Week 3) to ERC-721 (Week 4)

In Week 3, students worked with the ERC-20 (Fungible Token) standard: tokens that are identical and fully interchangeable (1 GCT ≈ 1 GCT) - Suitable for currency, uniform Carbon Credit, and reward points.

When each asset is unique and non-interchangeable, we need the ERC-721 (Non-Fungible Token - NFT) standard: each Token is tied to a unique tokenId - Suitable for a Solar Farm project certificate, a land-use rights deed, or an organic produce shipment.

CriteriaERC-20ERC-721
FungibilityFungibleNon-Fungible
Identifier (tokenId)NoneRequired (uint256)
DivisibilityYes (via decimals)No (whole Token ID)
Typical useCarbon Credit, Stablecoin, PaymentGreen Certificate, RWA, Supply Chain Batch
Data managementbalanceOf[address]ownerOf[tokenId], tokenURI[tokenId]

02 · REAL-WORLD ASSETS

Real-World Assets (RWA) and the "Token ≠ real asset" boundary

Real-World Assets (RWA) is the process of digitizing physical assets (real estate, green bonds, energy certificates, agricultural produce) into Tokens on the Blockchain.
Real asset (Off-chain) ↓ Verification / Legal Oracle / Issuer ↓ Mint NFT Blockchain Record
A key principle: Tokenization does not automatically carry off-chain legal value if there is no legal framework and independent verifier. It requires an accompanying legal mechanism, ownership regulations, a verification body, a Smart Contract, and an off-chain asset management process. Tokenization is a technology + legal + governance + verification problem, not merely a technology problem.

03 · METADATA & IPFS

Metadata structure, IPFS & Immutable Architecture

Because Gas costs on the Blockchain are expensive, documents, images, and legal text are not stored directly on-chain but instead uploaded to IPFS (InterPlanetary File System) - A decentralized data storage and distribution system.

BLOCKCHAIN NETWORK
tokenId1001
owner0xAlice...
statusACTIVE
IPFS STORAGE
Metadata JSON
High-res PDF Doc
Sensor Image Data

↓ tokenURI(tokenId) on the Blockchain returns a path such as ipfs://QmXyz.../metadata.json pointing to the data stored on IPFS.

Content Identifier (CID): Data on IPFS is retrieved by a content hash (ipfs://Qm...). If a file is modified by even 1 byte, the CID changes completely - Preventing tampering with Metadata content.

04 · GREENWASHING & CHAIN OF CUSTODY

The Greenwashing problem & Chain of Custody in supply chains

Greenwashing is when a company makes a "green" claim without certification or with misleading data.

Blockchain's role: Blockchain does not itself verify whether input data is real or fake ("Garbage In, Garbage Out"), but it does guarantee transparency, irreversibility, and a complete transaction history (Chain of Custody) from Farm ➜ Processor ➜ Carrier ➜ Consumer.

05 · PART B - SMART CONTRACT PRACTICE (VYPER)

The GreenCertificateNFT.vy Smart Contract

Source code for a simplified ERC-721 implementation for green certification:

# @version ^0.4.3

"""
@title GreenCertificateNFT
@notice Smart Contract quản lý NFT Chứng nhận Dự án Xanh / Lô hàng Chuỗi cung ứng
"""

# Khai báo Event
event Transfer:
    sender: indexed(address)
    receiver: indexed(address)
    tokenId: indexed(uint256)

event Approval:
    owner: indexed(address)
    approved: indexed(address)
    tokenId: indexed(uint256)

event CertificateIssued:
    tokenId: indexed(uint256)
    owner: indexed(address)
    metadataURI: String[256]

event CertificateRevoked:
    tokenId: indexed(uint256)
    reason: String[100]

# Trạng thái Chứng nhận
enum CertStatus:
    ACTIVE
    EXPIRED
    REVOKED

# State Variables
name: public(String[32])
symbol: public(String[8])

admin: public(address)
total_supply: public(uint256)

# Mappings
ownerOf: public(HashMap[uint256, address])
balanceOf: public(HashMap[address, uint256])
getApproved: public(HashMap[uint256, address])
tokenURI: public(HashMap[uint256, String[256]])
statusOf: public(HashMap[uint256, CertStatus])

@deploy
def __init__():
    self.name = "Green Certificate NFT"
    self.symbol = "GCNFT"
    self.admin = msg.sender
    self.total_supply = 0

@external
def mint(to: address, tokenId: uint256, uri: String[256]):
    """
    @notice Phát hành NFT Chứng nhận Xanh mới
    """
    assert msg.sender == self.admin, "Only Admin can mint"
    assert to != empty(address), "Invalid recipient"
    assert self.ownerOf[tokenId] == empty(address), "Token ID already exists"

    self.ownerOf[tokenId] = to
    self.balanceOf[to] += 1
    self.tokenURI[tokenId] = uri
    self.statusOf[tokenId] = CertStatus.ACTIVE
    self.total_supply += 1

    log Transfer(empty(address), to, tokenId)
    log CertificateIssued(tokenId, to, uri)

@external
def approve(approved: address, tokenId: uint256):
    owner: address = self.ownerOf[tokenId]
    assert owner != empty(address), "Token does not exist"
    assert msg.sender == owner, "Not the token owner"

    self.getApproved[tokenId] = approved
    log Approval(owner, approved, tokenId)

@external
def transferFrom(sender: address, recipient: address, tokenId: uint256):
    """
    @notice Chuyển nhượng NFT Chứng nhận giữa các bên trong chuỗi cung ứng
    """
    assert self.ownerOf[tokenId] == sender, "Sender is not owner"
    assert recipient != empty(address), "Invalid recipient"
    assert msg.sender == sender or msg.sender == self.getApproved[tokenId], "Not authorized"
    assert self.statusOf[tokenId] == CertStatus.ACTIVE, "Cannot transfer revoked certificate"

    # Reset approval
    self.getApproved[tokenId] = empty(address)

    # Update Balances & Ownership
    self.balanceOf[sender] -= 1
    self.balanceOf[recipient] += 1
    self.ownerOf[tokenId] = recipient

    log Transfer(sender, recipient, tokenId)

@external
def revokeCertificate(tokenId: uint256, reason: String[100]):
    """
    @notice Tác vụ thu hồi chứng nhận khi phát hiện sai phạm / Greenwashing
    """
    assert msg.sender == self.admin, "Only Admin/Auditor can revoke"
    assert self.ownerOf[tokenId] != empty(address), "Token does not exist"
    assert self.statusOf[tokenId] == CertStatus.ACTIVE, "Certificate not active"

    self.statusOf[tokenId] = CertStatus.REVOKED
    log CertificateRevoked(tokenId, reason)
Why not delete the NFT when revoking it? Blockchain is meant to preserve history. Instead of deleting the NFT, the system just changes statusOf[tokenId] from ACTIVE to REVOKED - Preserving the entire issuance/transfer/revocation history, which is exactly the value Blockchain brings to traceability.

06 · TESTING WITH APE FRAMEWORK

Interaction test script (Ape Framework)

from ape import accounts, project

def main():
    admin = accounts.test_accounts[0]
    farm = accounts.test_accounts[1]
    distributor = accounts.test_accounts[2]

    # 1. Deploy Contract
    nft = admin.deploy(project.GreenCertificateNFT)

    # 2. Mint NFT Chứng nhận cho Cà phê Hữu cơ (Batch #1001)
    metadata_ipfs = "ipfs://QmXoypizjW3WknFiJnKLwHCnL72vedxjQkDDP1mXWo6uco/metadata.json"
    nft.mint(farm.address, 1001, metadata_ipfs, sender=admin)

    print(f"Owner of Token 1001: {nft.ownerOf(1001)}")
    print(f"Token URI: {nft.tokenURI(1001)}")

    # 3. Nông trại chuyển nhượng lô hàng (và NFT đính kèm) cho Nhà phân phối
    nft.transferFrom(farm.address, distributor.address, 1001, sender=farm)
    print(f"New Owner after transfer: {nft.ownerOf(1001)}")

    # 4. Kiểm toán viên (Admin) phát hiện vi phạm, thu hồi chứng nhận
    nft.revokeCertificate(1001, "Failed organic residue test on-site", sender=admin)
    print(f"Certificate Status (2 = REVOKED): {nft.statusOf(1001)}")

07 · PART C - IPFS IN PRACTICE

Creating Metadata & uploading to IPFS

Students initialize a metadata.json file representing 1 shipment/green certificate:

{
  "name": "Organic Coffee Batch #2026-001",
  "description": "Chứng nhận Cà phê Hữu cơ xuất khẩu - Lâm Đồng",
  "image": "ipfs://QmZ4tDuvesSSp1D2C2A1k5UvG8wF3eH4k1xP9L/coffee.jpg",
  "attributes": [
    { "trait_type": "Project", "value": "Lam Dong Organic Farm" },
    { "trait_type": "Capacity/Quantity", "value": "2000 kg" },
    { "trait_type": "Harvest Date", "value": "2026-08-10" },
    { "trait_type": "Certification Standard", "value": "USDA Organic" },
    { "trait_type": "Auditor", "value": "Global Green Verification Corp" }
  ]
}

Upload & link process

  1. Use the IPFS CLI or a Pinning service (Pinata/Infura)
  2. Upload the image file ➜ receive an image_cid
  3. Fill in image_cid inside metadata.json ➜ upload metadata.json ➜ receive a metadata_cid
  4. Pass ipfs://<metadata_cid> into the mint() function on the Smart Contract

08 · PART D - DATA & RESEARCH

Graph Analytics for the On-chain supply chain

Build a graph model G = (V, E) from on-chain Transfer events: Node (V) is a wallet representing a Farm, Factory, Logistics provider, Distributor, or Retailer; Edge (E) is an NFT transfer transaction (transferFrom) carrying timestamp and tokenId data.

import networkx as nx
import matplotlib.pyplot as plt

# Khởi tạo đồ thị chuỗi cung ứng
G = nx.DiGraph()

# Thêm các giao dịch chuyển nhượng từ Event Logs
events = [
    ("Farm_A", "Processing_B", 1001),
    ("Processing_B", "Distributor_C", 1001),
    ("Distributor_C", "Retailer_D", 1001),
    ("Farm_A", "Company_X", 1002),  # Luồng bất thường
    ("Company_X", "Retailer_D", 1002)
]

for sender, receiver, token_id in events:
    G.add_edge(sender, receiver, label=f"NFT #{token_id}")

# Tính toán các chỉ số Graph Analytics
degree_centrality = nx.degree_centrality(G)
print("Degree Centrality:", degree_centrality)

# Phát hiện điểm bất thường (ví dụ: luồng đi qua node trung gian không có chứng chỉ)
print("Shortest Path (1001):", nx.shortest_path(G, "Farm_A", "Retailer_D"))

Combining IoT Sensors + Oracle + Smart Contract

11 · IN-CLASS DISCUSSION QUESTIONS

Discussion questions
