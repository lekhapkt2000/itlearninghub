01 · PART A - ON-CHAIN DATA

What is On-chain Data?

Week 6 is the Integration Week for the whole IS355 course. Where previous weeks each focused on a single component - Smart Contract, Token, NFT, DeFi, and ESG - this week students connect them into one complete system:

Blockchain ↓ On-chain Data ↓ Data Processing ↓ AI / Machine Learning ↓ Risk / Fraud Prediction ↓ DApp Dashboard
On-chain Data is data recorded and verified on the Blockchain: Transaction Hash, From/To Address, Value, Gas, Timestamp, Block Number, Contract Address.

Students need to distinguish the basic Blockchain data components:

ComponentRole
TransactionA single transfer of value/function call between two addresses, with its own identifying Hash
BlockA set of Transactions packaged and chained together over time
AddressThe identifier for a user (EOA) or Smart Contract on the Blockchain
Smart ContractA program that stores State and processes on-chain logic
EventA record a Smart Contract emits when an important state change occurs
Token TransferA Token transfer event (ERC-20/ERC-721) between two addresses

A Transaction has a typical data structure:

Transaction ├── Hash ├── From ├── To ├── Value ├── Gas ├── Gas Price ├── Nonce ├── Block Number └── Timestamp

Blocks chain together one after another, each Block containing many Transactions - This is the basis for analyzing transaction counts, transaction value, activity over time, and each address's activity along a timeline.

02 · PART B - EVENT LOGS

Event Logs

Besides ordinary Transactions, a Smart Contract also generates its own data through State, Transactions, and Event Logs. For the GreenLending.vy contract built in Week 5, Events such as LoanCreated, LoanRepaid, and LoanLiquidated are an excellent data source for Analytics.

event LoanCreated:
    loan_id: indexed(uint256)
    borrower: indexed(address)
    amount: uint256

When loan #001 is created with Borrower = 0xABC, Amount = 10,000, the Blockchain records the Event:

LoanCreated ├── loan_id = 001 ├── borrower = 0xABC └── amount = 10,000

A DApp can use Events to build an entire analytics flow:

Transaction History ↓ Analytics ↓ Dashboard ↓ AI Dataset

From an Event sequence LoanCreated ➜ LoanCreated ➜ LoanRepaid ➜ LoanCreated ➜ LoanLiquidated ➜ LoanCreated, you can immediately compute: Total Loans, Active Loans, Repaid Loans, Liquidated Loans, Default Rate.

03 · PART C - BLOCKCHAIN ANALYTICS

Blockchain Analytics

Blockchain Analytics is the process of collecting, processing, and analyzing Blockchain data to extract meaningful information.
Blockchain ↓ Data Collection ↓ Data Cleaning ↓ Feature Engineering ↓ Analysis / AI ↓ Visualization

With Green Lending data, three main groups of metrics can be analyzed:

Metric groupExamples
Transaction MetricsTransaction Count, Transaction Volume, Gas Used, Average Gas, Active Addresses
Lending MetricsTotal Loans, Total Loan Value, Average Loan, Average Interest, Default Rate, Liquidation Rate

04 · PART D - CONNECTING TO BLOCKCHAIN WITH WEB3.PY

Data Pipeline: Connecting to Blockchain with Web3.py

The full data architecture of an Analytics system:

Blockchain ↓ RPC / API (Alchemy, Infura) ↓ Data Extraction (Web3.py) ↓ Pandas DataFrame ↓ ML Model ↓ DApp Dashboard

Connect via RPC and check the connection status:

from web3 import Web3

w3 = Web3(Web3.HTTPProvider("YOUR_RPC_URL"))

print(w3.is_connected())  # True

Read a specific Block:

block = w3.eth.get_block(100)
print(block)
# Block Number, Timestamp, Transactions, Gas Used, Gas Limit

Read a specific Transaction:

tx = w3.eth.get_transaction("TRANSACTION_HASH")
print(tx)
# from, to, value, gas, gasPrice, nonce, blockNumber

Query all LoanCreated Events from the Green Lending Smart Contract (ABI compiled from the Vyper source in Week 5) and convert them into a pandas.DataFrame:

from web3 import Web3
import pandas as pd

# 1. Kết nối RPC và khởi tạo Contract
w3 = Web3(Web3.HTTPProvider("https://eth-sepolia.g.alchemy.com/v2/YOUR_API_KEY"))
contract_address = "0xYourGreenLendingContractAddress"
contract_abi = [...]  # ABI được biên dịch từ Vyper ở Tuần 5

contract = w3.eth.contract(address=contract_address, abi=contract_abi)

# 2. Truy vấn Event "LoanCreated" từ Block quá khứ
event_filter = contract.events.LoanCreated.create_filter(fromBlock=1000000, toBlock='latest')
events = event_filter.get_all_entries()

# 3. Chuyển đổi dữ liệu Event thành Pandas DataFrame
loans_data = []
for event in events:
    args = event['args']
    loans_data.append({
        'loan_id': args['loan_id'],
        'borrower': args['borrower'],
        'amount': args['amount'] / 10**18,       # Convert Wei to ETH
        'collateral': args['collateral'] / 10**18,
        'esg_score': args['esg_score']
    })

df = pd.DataFrame(loans_data)
df['collateral_ratio'] = (df['collateral'] / df['amount']) * 100

05 · PART E - MACHINE LEARNING FOR BLOCKCHAIN

Machine Learning for Blockchain

Blockchain stores a huge amount of data, but a lot of data doesn't mean humans can spot every anomalous behavior. AI can help with:

Transaction Data ↓ Feature Engineering ↓ Machine Learning ↓ Risk Score

Fraud Detection

Compare the behavior of a normal address against an anomalous one:

AddressTransaction frequencyAverage value
Normal10 transactions/day$500
Anomalous1,000 transactions/hour$50,000

When a deviation from the norm is detected, the system can flag it as ⚠ Suspicious Activity.

Anomaly Detection

Some commonly used Features: Transaction Frequency, Transaction Value, Unique Addresses, Gas Usage, Time Interval, Token Transfer.

Normal: 10 ➜ 20 ➜ 15 ➜ 18 transactions Abnormal: 10 ➜ 12 ➜ 15 ➜ 1,500

Algorithms

GroupTypical algorithms
Unsupervised LearningIsolation Forest, One-Class SVM, DBSCAN
Supervised LearningLogistic Regression, Random Forest, XGBoost

Feature Engineering

From raw transaction data, aggregate into a Feature Vector for each address:

Address A Tx Count = 150 Avg Value = 850 Unique Addresses = 37 Avg Interval = 2.5h

06 · PART F - GRAPH ANALYTICS & AML

Graph Analytics & AML

Blockchain can be represented as a graph: Address = Node, Transaction = Edge. A single transaction may not reveal anything unusual, but the entire network can expose hidden structures.

A ➜ B ↓ B ➜ C ↓ C ➜ D ↓ D ➜ A (Circular Transaction)
A Circular Transaction does not automatically mean money laundering - It is only a signal that warrants further analysis.

Graph Analytics helps uncover structures that single-transaction analysis struggles to see: a Hub Address (a fund-collecting wallet), a Transaction Cluster, Circular Transactions (fund loops), Peeling Chains, and abnormal Fund Flow.

AML - Anti-Money Laundering is the systems and processes used to detect, prevent, and report activity related to money laundering.
Transactions ↓ Risk Engine ↓ Risk Score ↓ Alert

A Risk Score is designed based on: Transaction Value, Transaction Frequency, Address History, Counterparty Risk, Transaction Pattern.

Risk ScoreLevel
0 - 0.3LOW
0.3 - 0.7MEDIUM
0.7 - 1.0HIGH

07 · PART G - SMART CONTRACT SECURITY

Smart Contract Security

A Smart Contract can directly manage Money, Token, Collateral, Loan, NFT - If it has a bug, assets can be lost or the system can behave incorrectly. Some common vulnerabilities students should know:

VulnerabilityDescription
ReentrancyA contract makes an External Call, and the recipient calls back into the contract before the State finishes updating
Access ControlAn unauthorized party is still able to call an important function (e.g., mint())
Integer/Arithmetic IssuesErrors related to arithmetic (overflow, underflow, rounding division)
Oracle ManipulationExternal data (asset price, ESG Score...) is manipulated before being fed into the Smart Contract
Logic ErrorsThe Smart Contract runs the code correctly but implements the wrong business logic

Example of a mint() function missing access control - Alice, Bob, Carol, and even an Attacker can all call it:

@external
def mint(amount: uint256):
    ...

A Smart Contract therefore needs a clear authorization mechanism: onlyOwner, onlyAdmin, or role-based access - Exactly how GreenLending.vy in Week 5 restricts createLoan() to admin and updateESGScore() to oracle.

08 · PART H - DAPP ARCHITECTURE

DApp Architecture

DApp - Decentralized Application is an application with part of its logic or data deployed on the Blockchain.

A typical DApp:

Frontend ↓ Web3 Provider ↓ Smart Contract ↓ Blockchain

If AI is integrated, the architecture gains an additional Off-chain processing branch:

Frontend ↓ Backend / AI API ↓ ML Model ↓ Blockchain

Suggested architecture for the IS355 Green Finance DApp:

┌──────────────────────────────┐ │ FRONTEND │ │ Streamlit / Web │ └──────────────┬───────────────┘ │ ↓ ┌──────────────────────────────┐ │ WEB3 / API LAYER │ └───────┬──────────────┬───────┘ │ │ ↓ ↓ ┌──────────────┐ ┌─────────────┐ │ Blockchain │ │ AI Engine │ │ Smart Contract│ │ ML Model │ └──────────────┘ └─────────────┘ │ │ └──────┬───────┘ ↓ Analytics Dashboard

For the Tech Stack, the Week 6 practice recommends:

Blockchain & Indexing

Web3.py / Ethers.js, Alchemy or Infura RPC, The Graph (GraphQL queries for Event Logs)

Data Processing & ML

Pandas, Scikit-learn (RandomForestClassifier, IsolationForest), NetworkX / PyTorch Geometric

DApp Frontend & Dashboard

Streamlit (recommended for fast prototyping) or Next.js + Wagmi + Recharts

Step 3 - Assess default risk with Scikit-learn & display it on Streamlit

With the sample data loan_data.csv:

ESGLoanCollateralInterestDefault
9210,00018,00050
858,00014,00060
6512,00013,00091
7215,00018,00071
import streamlit as st
from sklearn.ensemble import RandomForestClassifier

# Giả định mô hình đã được huấn luyện trước đó
# X: [esg_score, collateral_ratio, amount], y: default_status (0: Paid, 1: Default)
model = RandomForestClassifier()

st.title("🌱 Green Finance Analytics & AI Risk Engine")

# Trực quan hóa chỉ số chính
col1, col2, col3 = st.columns(3)
col1.metric("Total Loans Executed", len(df))
col2.metric("Average ESG Score", f"{df['esg_score'].mean():.1f}")
col3.metric("Avg Collateral Ratio", f"{df['collateral_ratio'].mean():.1f}%")

# AI Prediction Panel cho khoản vay mới
st.subheader("🤖 AI Loan Risk Assessor")
input_esg = st.slider("ESG Score", 0, 100, 75)
input_collateral_ratio = st.number_input("Collateral Ratio (%)", value=130.0)
input_amount = st.number_input("Loan Amount (ETH)", value=5.0)

if st.button("Analyze Risk"):
    # Giả lập dự đoán xác suất vỡ nợ từ Model
    risk_prob = model.predict_proba([[input_esg, input_collateral_ratio, input_amount]])[0][1]

    if risk_prob > 0.7:
        st.error(f"🔴 HIGH RISK (Default Probability: {risk_prob*100:.1f}%)")
    elif risk_prob > 0.3:
        st.warning(f"🟡 MEDIUM RISK (Default Probability: {risk_prob*100:.1f}%)")
    else:
        st.success(f"🟢 LOW RISK (Default Probability: {risk_prob*100:.1f}%)")

A minimal Dashboard layout for the prototype:

GREEN FINANCE ANALYTICS ──────────────────────────── Total Transactions 1,254 Total Loans 327 TVL $2.4M Average ESG 82.5 Default Rate 4.1% ──────────────────────────── [Transaction Chart] [ESG Distribution] [Risk Distribution] ──────────────────────────── Recent Transactions
AI should not write the entire Model directly onto the Blockchain - Gas cost is extremely high for matrix/loop computation, and the EVM does not support complex floating-point numbers well. Solution: run ML Off-chain (Backend/Cloud), and only push the prediction result or a zkML proof On-chain via an Oracle if needed.
