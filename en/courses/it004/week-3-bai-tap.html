QUESTION 1 (SAMPLE) · GROUP BY & HAVING

Filter classes with 5 or more members

Exercise: Count the number of registered members for each class, showing only classes with 5 or more members.

SELECT MaLop, COUNT(*) AS SoHocVien
FROM DangKy
GROUP BY MaLop
HAVING COUNT(*) >= 5;
WHAT IS IT?

GROUP BY groups rows that share the same MaLop into 1 group; HAVING filters on the grouped result (unlike WHERE).

WHY?

WHERE runs before grouping, so it can't be used with a group's COUNT(*). The condition "5 or more members" only makes sense after the counting is done, so it has to be filtered with HAVING.

QUESTION 2 (SAMPLE) · RELATIONAL DIVISION

Trainer teaching all classes in "Gym A" room

Exercise: Find the trainer who teaches all the classes held in the "Gym A" room (missing none).

SELECT hlv.HoTen
FROM HuanLuyenVien hlv
WHERE NOT EXISTS (
    SELECT lt.MaLop
    FROM LopTap lt
    JOIN PhongTap p ON lt.MaPhong = p.MaPhong
    WHERE p.TenPhong = N'Gym A'
    AND NOT EXISTS (
        SELECT 1 FROM LopTap lt2
        WHERE lt2.MaLop = lt.MaLop AND lt2.MaHLV = hlv.MaHLV
    )
);
WHAT IS IT?

Relational division finds rows in table A (trainers) that satisfy the condition against every corresponding value in table B (Gym A's classes).

WHY?

SQL Server has no direct division operator, so you have to reason in reverse: "there is no class in Gym A that this trainer has not taught" - nested NOT EXISTS is used to simulate division.
