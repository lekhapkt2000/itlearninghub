  11. When assigning a subject to be taught, the prerequisite order between subjects must be respected (a subject may only be taught after its prerequisite subjects have been completed).

QUESTION 1 (SAMPLE) · TRIGGER AFTER INSERT

Automatically increment session count on a new schedule entry

Exercise: Whenever a new row is added to LICHTAP, automatically add 1 to the corresponding member's SoBuoiTap.

CREATE TRIGGER trg_CapNhatSoBuoi
ON LichTap
AFTER INSERT
AS
BEGIN
    UPDATE HocVien
    SET SoBuoiTap = SoBuoiTap + 1
    WHERE MaHV IN (SELECT MaHV FROM inserted);
END;
WHAT IS IT?

AFTER INSERT is a trigger that runs automatically right after a row is added to a table; the virtual table inserted holds the row(s) just added.

WHY?

SoBuoiTap needs to stay in sync automatically, regardless of whether the developer remembers to run a manual UPDATE - the trigger guarantees the data stays consistent.

QUESTION 2 (SAMPLE) · TRIGGER INSTEAD OF DELETE

Block deletion of a room that still has classes

Exercise: Do not allow a gym room to be deleted if there are still classes assigned to it.

CREATE TRIGGER trg_ChanXoaPhong
ON PhongTap
INSTEAD OF DELETE
AS
BEGIN
    IF EXISTS (
        SELECT 1 FROM LopTap lt
        JOIN deleted d ON lt.MaPhong = d.MaPhong
    )
        RAISERROR(N'Phòng đang có lớp, không thể xóa.', 16, 1);
    ELSE
        DELETE FROM PhongTap WHERE MaPhong IN (SELECT MaPhong FROM deleted);
END;
WHAT IS IT?

INSTEAD OF DELETE completely replaces the default DELETE behavior with your own custom logic.

WHY?

The condition needs to be checked before the deletion actually happens. Using AFTER DELETE would mean the data is already gone by the time the check runs - too late to stop it.
