QUESTION 1 (SAMPLE) · JOIN + GROUP BY + ORDER BY

Class with the most registered members

Exercise: Find the class name with the highest number of registered members.

SELECT TOP 1 lt.TenLop, COUNT(*) AS SoHocVien
FROM LopTap lt
JOIN DangKy dk ON lt.MaLop = dk.MaLop
GROUP BY lt.TenLop
ORDER BY COUNT(*) DESC;
WHAT IS IT?

Combines JOIN (to get the class name), GROUP BY (to count per class), and ORDER BY ... DESC + TOP 1 (to take the class with the most members).

WHY?

This is a typical example of chaining several learned techniques together: you must JOIN first to get the class name, GROUP BY to count per class, and only then sort and take the first row - doing the steps out of order produces a wrong result or a syntax error.

QUESTION 2 (SAMPLE) · CREATE TABLE + CONSTRAINT + DML

Comprehensive exercise: create a table and manipulate data

Exercise: Create the table THANHVIEN(MaTV, HoTen, Email) with Email unique, then insert 1 sample row.

CREATE TABLE ThanhVien
(
    MaTV INT PRIMARY KEY,
    HoTen NVARCHAR(50) NOT NULL,
    Email NVARCHAR(100) UNIQUE
);

INSERT INTO ThanhVien (MaTV, HoTen, Email)
VALUES (1, N'Nguyễn Văn An', 'an@uit.edu.vn');
WHAT IS IT?

UNIQUE ensures no 2 rows have the same Email value; this is a different constraint from PRIMARY KEY (a table has only 1 primary key but can have multiple UNIQUE columns).

WHY?

MaTV is already the primary key that identifies each record, but the exercise also requires Email to be non-duplicate - this is a separate business rule, so UNIQUE must be added rather than reusing PRIMARY KEY.
